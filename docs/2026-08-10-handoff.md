## 2. The one thing to understand before touching the grammar

The composition grammar works and the Site kit solves. **What it generates is not yet a room**, and the
reason is measured rather than felt.

Rendered proof, six seeds before and after the weight correction:
<https://claude.ai/code/artifact/57fb013d-d690-4d8e-88d7-b57986d5b297>

**Uniform per prototype was not uniform per tile.** A symmetric tile dedupes to one prototype; an
asymmetric one keeps four. So a flat weight made `tile_floor` a quarter as likely as its neighbours —
7.4% of 864 cells against ~23% each for the other three, with the prediction from prototype counts
alone (4/4/4/1) matching the measurement to within half a point. That identified it as an artifact of
the representation rather than a taste question. Fixed in `36abd66`: one authored tile carries one
unit of weight, split across the turns it survived as.

After: floor 19.2%, doorways 12.4%, and the plans have interiors.

**Two things that correction did not fix, and both are for FVS-R-9 to read rather than for anyone to
tune:**

- **`Empty` went 21% → 36%.** It still carries a full unit while the four authored tiles now sum to
  four between them, so scaling the tiles down scaled the holes up. Left as measured. Tuning it now
  is picking a hole density by feel, which is exactly what §4's committed thresholds exist to decide.
- **Seeds 4, 5 and 6 come out near-identical**, before and after. That is a hot-spot signature and it
  is about adjacency being tight over a four-tile alphabet, not about weights. FVS-R-5 already counted
  **nine missing tile kinds**; if FVS-R-9 confirms a narrow range, the answer is more tiles, not a
  cleverer objective.

**Do not add authored weights before FVS-R-9 runs.** The author's standing decision is ship uniform
and measure it, and the reason has already paid off once: the first distribution was measuring the
representation, so authored weights would have baked an artifact in invisibly.

## 3. FVS-R-7 — what landed and what is left

**Landed.** `composition::agrees` is the substitutable adjacency rule and
`grammar::from_compositions` takes it as a **parameter** — Karth & Smith's *"any arbitrary adjacency
validity function can be substituted here… without changing the WFC solver itself."* A test drives the
learner twice with opposite rules and asserts the supports differ; inlining the comparison, the way
`declared` does it, fails it by name. That is what keeps FVS-R-11's edge-versus-corner question from
gating anything.

**Four turns per tile, and that is what made the kit solvable at all.** Measured before it existed:
every wall tile's north support was `Empty` and nothing else. A wall presents `wall` outward on one
face, so the tile across that seam has to present `wall` back — and only the same tile turned 180°
does. The turned interface is **derived, not rotated**: `turn_composition` turns the members through
`rotate_xz` and `add_yaw`, the pair a stamp already turns by, and re-derives the face. There is no
second sign convention to get backwards, which `rotate_xz`'s own doc warns costs you a mirror with no
test going red.

**Left:** the editor cannot drive it. `generate_from` has `Source::{Learned, Declared}` and needs a
third. The catch worth knowing before starting: `solve` returns `Placed` rows, and a composition
prototype names a **composition**, so the write-back has to become `Stamped` rows, not placements.
A `grammar::as_stamps`-shaped helper beside the grammar is the clean place for that translation.

## 4. Traps paid for today — read these before repeating them

**A test that cannot fail is worse than no test, and this cost three rounds.** The pattern: a system
that needs a viewport can only be tested through the part that does not.

- `over_ui` first read `bevy_picking`'s `Hovered`, which is written from the **window's** cursor — the
  one `sense_pointer` deliberately never moves. So it was false for an injected pointer and false for
  an author who moved the mouse off the row they had just clicked. Unreachable by any test, reported
  twice as the feature not working. It reads the layout now, through
  `ComputedNode::contains_point` — the function `bevy_ui`'s own picking backend calls.
- The first UNDER-readout test drove the whole app and **passed with the rule deleted**, because
  headless has no viewport so the line is blank either way. Mutation-testing caught it.
- The fix that works, three times now: **extract the decision** — `edit_subject`, `under_readout`,
  `ghost_anchor`, `pick_along` — so a test can ask it directly.

**Every new assertion this batch was mutation-tested.** Keep doing that; it is what caught the above.

**An injected cursor cannot be over the interface.** `Hovered` is false for everything, so a BRP-driven
click passes straight *through* a panel — mine placed a floor tile while trying to arm a palette row.
An agent cannot reproduce a pointer-over-UI report at all. Budget for that.

**Kill by PID, never by pattern.** `pkill -f 'emerge-mapper . site_67'` is a regex that can match more
editors than you mean.

## 6. Two things the author decided today, so nobody re-litigates them

- **A lit wall is a tag, shaped as Cooper's second layer** (`10.1609/aiide.v18i1.21944`) — FVS-R-6,
  archived. Costs FVS-R-8 **one field** on `Composition`, not a second prototype family.
- **`Mount::Overlay` is `Mount::Decal`.** The old name read as "sits on the floor", which is true of
  almost everything, and a labelling pass moved four solid pieces onto it — leaving them out of the
  overlap rule entirely. Renamed so the mistake is not authorable, including the tokens the VLM reads
  (`overlay_floor` → `decal_floor`).

Still open from that audit, both documentation rather than defects: the `Mount` family names *where a
piece sits* while deciding *what it contests* (the contest column lives only in `same_layer`'s arms),
and `blocking` is a plan-only 2-D test whose bounded claim is stated nowhere. Also: `site/floor` and
`site/wall` still carry `front: Some(South)` from the labelling pass — meaningless on a 1×1 floor tile
rather than harmful, since no rule reads it, but the same over-claim that produced two reverts.
