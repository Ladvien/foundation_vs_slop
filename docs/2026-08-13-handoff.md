## The one-line version

The debugger gained the direction it never had — **agent → human** — and was then corrected five

## What exists now

**`bevy_debugger/guide`** posts a script and the app renders **one step** over its own window.
**`bevy_debugger/guide+watch`** waits on a condition the *host* named, advances itself, and records
`k/n` per step. A step is Carroll's guided-exploration card: label, why, 2–4 hints, a **checkpoint**,
and **recovery**.

- Plugin: `crates/bevy_debugger_mcp/crates/bevy_debugger_bevy/src/guide.rs`
- MCP tool: `guide`, in **`secure_mcp_tools.rs`** — see the trap about two tool tables below
- Editor vocabulary: `crates/emerge-mapper/src/guided.rs` (13 conditions)
- Scripts: `crates/emerge-mapper/guides/*.json`
- Helpers: `scripts/guide_post.sh` (waits for BRP, then posts), `scripts/guide_devshot.sh` (capture)

## Where the site kit stands — read this before authoring

`assets/emerge/site/compositions.ron` has **four tiles**, and the kit had none before today.

| tile | contents | state |
|---|---|---|
| `site/tile_1` | `site/floor` | good |
| `site/tile_2` | floor + `site/wall` flush at −0.45 | good |
| `site/tile_3` | floor + two walls, one turned 90° | good — a real corner |
| `site/tile_4` | floor + `site/wall_low` **at (0,0)** | **wrong** |

**`site/tile_4` is not flush.** Its low wall sits dead centre, so all four faces derive as *open* and
the solver treats it as a second floor tile — placeable anywhere a floor goes, including where a wall
belongs. Fix it in the editor: `3`, then `right` `right` to reopen it, then `shift`+arrow to flush the
low wall (it is 0.2 × 1.0, so flush is ±0.4).

**The tiles are solver-usable** — this was checked, and it is what the whole exercise was for:
4 compositions → **10 prototypes, 10 face interfaces, 0 skipped**
(`the_site_kit_tiles_become_solver_prototypes`). More prototypes than tiles because a tile is a
quarter-turn object: a symmetric floor yields one, a wall or corner yields four.

**Two pieces can never be one-cell tiles**, measured: `site/wall_doorway` is 2.06 m and
`site/wall_window` is 2.0 m. What a doorway tile should *be* in this kit is an open design question —
do not script one without asking.

## Traps paid for — do not re-learn these

**The transcript can lie if a checkpoint is weaker than its step.** `the tile is saved` asked whether
*whatever is currently open* is committed, so it said yes for a tile saved ten minutes earlier: a step
reported 1/1 for a corner tile that did not exist. Checkpoints now take arguments (`Step::with` →
`In<Value>`). **Prefer a monotonic condition** — `the kit has tiles {n}` counts what is committed and
a count cannot go down, so revisiting old work cannot re-satisfy it.

**A green suite is not evidence that something a human reads is right.** Two overlay bugs survived 15
passing tests and were found in the first two devshot captures. Both branches rendered text; nothing
asserted *which*.

**The watch stream is Server-Sent Events**, not JSON lines — `data: {json}\n\n`
(`bevy_remote-0.19.0/src/http.rs:451`). A reader that hands the raw line to a JSON parser never parses
and never says so; it accumulates in silence, which looks exactly like a run where nothing is
happening. Four checkpoints passed unreported that way.

**The MCP server has two tool tables.** `secure_mcp_tools.rs` (`SecureMcpTools`, advertised as
`bevy-debugger-mcp-secure`) is what the binary serves; `mcp_tools.rs` (`BevyDebuggerTools`) is
constructed by `mcp_server_v2` and re-exports the request structs. **Neither is dead.** A tool added
to the wrong one gets `tool not found` from a running server. Verify by driving the built binary over
stdio (`initialize` → `tools/list`), not by reading source. Anything written in both is a rule with
two copies — the collaboration protocol is one `COLLABORATION_PROTOCOL` const.

**The installed MCP binary was built from the wrong repo, for months.** `cargo install --path
crates/bevy_debugger_mcp` on 2026-08-13 reported *Replaced package `bevy_debugger_mcp
(/Users/ladvien/bevy_debugger_mcp)`* — the pre-vendoring **sibling clone**, still on disk and last
touched at `f428b85`. So every agent using the debugger was running a binary built from a repo that
is not the source of truth, and any fix made under `crates/` could never have reached it. That is the
two-paths hazard the vendoring existed to remove, surviving one layer out in what was installed
rather than in what was compiled. **Install from `crates/bevy_debugger_mcp` and check the path cargo
prints**; the sibling clone should be deleted once nothing is left in it worth keeping.

**BRP handlers run in `RemoteLast`**, a schedule inserted *after* `Last`. **Screenshot captures
offscreen**, never the primary window — so it cannot see any UI at all.

**macOS 26.5 will not let a script raise a window.** `osascript ... set frontmost of (first process
whose unix id is $PID)` is accepted and does nothing; a freshly launched window does not come up in
front either. Every frame taken that way is **exactly 55,654 bytes** of black.
`scripts/guide_devshot.sh` waits for a human to click instead. And never launch the editor with
`cargo run` for a capture — cargo forks it as a child, so `$!` is cargo's pid.

**Never `cargo run -p emerge-mapper & curl ...`.** The editor takes ~10 s to open a window and bake
thumbnails; the curl fails with an empty reply and the app comes up with no script. This happened
three times in one session. Use `scripts/guide_post.sh`.

## Writing a guide script — what went wrong four times

`the_tile_authoring_script_can_actually_be_followed` drives the shipped JSON and asserts each
checkpoint goes **false → true at its own step**. It found four wrong steps in a script written with
the source open, every one of which passed the name check because every *name* existed:

- the Tiles tab is `3`; the script said `4`, which is Compose
- "derive the edges" watched a condition written by `B` on the **Meshes** tab off a *mesh's* subgrid
- "press N and name it" measured nothing — the tab already opens a blank tile
- "press Enter again, pick a wall" would have dropped a second **floor**: `TileListNext` is bound at
  `Stance::Idle` only, so the arrows cannot walk the library while a piece is in hand

Two kinds of step, and the distinction matters to the test: an **action** step must find its condition
false on arrival or it measures nothing; an **observation** step presses nothing and asserts what the
previous step left behind.

And a step with `checkpoint: null` **never advances on its own** — it is the question a machine cannot
answer. Say so in chat, by name, and wait for a real answer before calling `skip`. The card promises
the author "tell the agent".
